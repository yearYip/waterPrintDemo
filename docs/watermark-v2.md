# 隐形水印与系统截图

新生成入口为 WatermarkGenerator.generate()，先尝试 FrequencyWatermark.embed()。
若载体不适合频域写入，则生成并回读验证 PNG 最低位水印，明确标记“仅原图提取”。
旧的 SpatialWatermark 只用于兼容早期图片，
不再参与新图片生成。新图片不拼接区域、不加定位边框。

## 为什么替换旧方案

旧方案对矩形格子整体调整亮度，在暗图中形成可见网格；原图本身的明暗差又会干扰
格子比较。单纯减少亮度偏移或重复格子，无法同时解决这两个问题。

参考项目：https://github.com/dragonxash/blind-watermark-studio

该项目 README 明确说明：

- FFT 分离需要加水印之前的原图，且不能缩放、裁剪、旋转。
- DWT-DCT-SVD 鲁棒隐写也要求图片尺寸与嵌入时一致。

因此没有直接复制其 FFT 或隐写实现。当前代码独立实现频域量化，并额外处理截图的
图片区域定位、归一化和小范围边界校正；与参考项目的文件格式不互通。

## 新编码

- 对完整图片建立 512×512 的规范坐标，保持传入照片本身的宽高。
- 每个 8×8 块只修改一个非直流 DCT 系数，避免整体抬高/降低矩形区域的亮度。
- 使用间距 20 的双陪集量化、512 个同步位，以及固定置乱的空间重复。
- 对最多 512 个消息位使用约束长度 7、码率 1/2 的卷积码，软判决 Viterbi 解码。
- 原有 WMK1 消息长度、Magic 和 CRC32 校验继续用于确认真正恢复了消息。
- 对原始亮度低于 48 的像素，每个 RGB 通道最多改变 1；其他像素最多改变 2。
  原始 Alpha 不变。纹理估计先扣除亮度渐变。
  浅色、平滑区域（平均亮度 96～254）可使用每通道最多 1 的弱信号；
  极暗平滑区域、纯白区域不强制加入频域信号。
- 写入后必须成功回读，并通过短边缩放到 384 像素后的回读检查，才允许返回成功。
  隐形强度下无法通过检查时不会提高强度，而是转为经过回读验证的 PNG 原图水印。
  主页持续显示是否通过缩放校验；仅原图模式不能保证截图、缩放或 JPEG 后的提取。

截图定位缓存只含最近 8 张图片的 64×64 灰度缩略图及宽高，存储在应用私有目录；
它只提出图片四角坐标，不用于查表返回溯源信息。
定位后的图片仍须通过同步位、纠错和消息 CRC32。

## 截图提取

1. 尝试完整所选图片的规范坐标解码。
2. 如果截图带有状态栏、按钮或留白，用本地缩略图匹配提出图片区域。
3. 根据同步位微调图片四角，并估计缩放导致的系数衰减。
4. 合并重复信号，用软判决纠错读取消息，验证 Magic、消息长度与 CRC32。
5. 没有本地缩略图或定位失败时，可以手选四个角。四角应位于截图中的完整照片边界，
   不应框选整张屏幕。旧格式提取作为兼容回退保留。

## 验证范围

遵循不编译 Android 工程的要求，没有执行 Gradle 或实机测试。
使用独立数值模型验证 DCT/QIM、卷积纠错、缩放和定位，不等同于 Android 端已验证。

模型中：

- 暗色纹理图（基准亮度 22）：最大像素改动 1，原图及短边 384 像素缩放图的数据位错误数均为 0。
- 普通与强纹理图：最大像素改动 2；强纹理缩放图约 7.3% 的编码位发生错误，
  纠错后的 512 个测试数据位全部恢复。
- 1080×1920 的模拟系统截图中，先定位 600×400 的图片区域，再微调边界，恢复全部数据位。
- 手选边界偏移约 2 像素的案例，校正前无法恢复，校正后数据位错误数为 0。
- 大面积近黑且无纹理的案例没有足够的截图载体，转为 PNG 原图模式。

后续低纹理兼容调整的独立数值模拟中，平均亮度 120、200、250、254 的纯色图片
（768×512）每通道最大改动均为 1，原图和缩放到 576×384 后的测试编码位错误数均为 0。
这仍是数学模型验证，不是 Android 编译或实机测试。

真实图片仍须在目标手机上检验视觉效果和解析率，不能据此承诺任意截图均可恢复。
极小显示尺寸、裁剪、不完整图片、重复有损压缩和相机拍屏不属于已验证条件。
参考项目本身也不保证缩放后提取成功。

旧图片不会自动变成新编码；更新后必须重新生成、保存，再截系统截图测试。
