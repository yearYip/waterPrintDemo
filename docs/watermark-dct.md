# 5.6.1：重复分块 DCT 水印与截图自动预处理

应用版本为 5.6.1，versionCode 为 17。本次新增截图留白自动识别、基于同步导频的尺度估计和对齐后重复消息合并；无需预先提供原图尺寸。用户提供的相册截图自动解析结果与原 PNG 一致，11 项解析回归测试及 6 项 JVM 单元测试通过。

本版保持原有生成和解析界面。生成端直接处理整张图片的 8×8 像素块：读取亮度通道的一对低频 DCT 系数差，用周期 80 的量化写入一位；只计算所需的系数差及对应的像素增量，不再对每块执行 Haar DWT、完整 DCT 和 SVD，也不再处理三个颜色通道。输出仍保存为 PNG。生成完成不自动回读。

消息继续使用 WMK3：用户 ID、设备 ID、毫秒时间戳、长度及 CRC32。对实际消息位使用 Hamming(7,4) 纠错后，在 16 行的块网格中重复；每行前四列是同步导频，其余列携带数据。网格宽度随消息长度变化，最短 12 列，最长 60 列。若用户 ID 为 6 个 ASCII 字符且设备 ID 可压缩为 8 字节，单个完整周期约为 256×128 原图像素。用户 ID 越长，完整周期越宽，小裁剪的回读机会越低。生成图片至少需容纳一整个周期。

解析端在最多 512×512 像素的中心区域搜索 8×8 像素相位、周期列数与消息起点，先由导频筛选候选，再解 Hamming 码并验证 WMK3 和 CRC32。对缩小图片另试若干上采样比例及系数增益。解析速度可能较慢。对旧版 DWT-DCT-SVD 水印的兼容回读没有纳入本版流程。

## 截图自动预处理

解析首先尝试原尺寸。失败后自动识别并去除近似纯色的上下、左右留白，小面积相册指示图标可被容忍；保留未裁剪图作为另一候选，避免把照片中的平坦区域误当作边框后丢失解析机会。图片、录屏帧和手动选区均使用同一解析流程。

对每个候选区域，在恢复尺寸为当前尺寸 0.5～2 倍的范围内逐像素扫描候选宽度，并按区域宽高比计算高度，不预设原图为正方形或 1080 像素。恢复宽度不超过 4096，像素总数不超过 800 万。扫描通过图片左侧四列同步导频的最多三个纵向重复周期评分，尝试不同系数增益，只对得分最高的最多 12 个尺寸做完整解码。重采样使用双线性过滤；对齐后在最多 1536×1536 的区域内合并重复消息，最终仍需通过消息格式和 CRC32 校验。

这个自动尺度估计针对完整图片经过等比例显示缩放、周围带近似纯色留白的截图。边界缺失、复杂界面遮挡、非等比例拉伸、旋转、透视和强压缩不保证恢复。普通局部裁剪继续使用原有相位搜索及固定倍率回退；完整图片的左上角导频假设不适用于任意局部截图。预处理无法补回已经丢失的水印信息。

`ScreenshotWatermarkTest` 覆盖非正方形图的非整数放大后 JPEG 90、非整数缩小后白边截图、黑白留白识别、大留白、小图诊断和纯色图边界。用户提供的相册截图通过可选的 `watermarkFixtureDir` instrumentation 参数读取（目录内为 `original.png` 和 `screenshot.jpg`），测试比较两者解出的完整载荷，不将私人照片打包进 APK。

本版模拟器验证覆盖原图 PNG、局部裁剪、JPEG 90、JPEG 85、整图缩至 50%、局部裁剪再缩至 50%、无水印图片拒绝及纯色图。模拟验证不能替代用户在真实照片、微信等软件处理后的测试。对于极小裁剪、强压缩、透视拍屏及用户 ID 较长的情况，不保证回读。
