# 5.1.3：移除生成时回读校验

此文档记录旧版实现。当前 5.6.1 的生成与解析方式见 [重复分块 DCT 水印](watermark-dct.md)。

应用版本为 5.1.3，versionCode 为 11。直接选择图片生成水印即可使用，没有额外开关。

## 5.1.3 生成流程

生成时不再执行频域原图与缩小图回读、区域 PNG 回读或 WebP 质量 75／50 的模拟检查，也不再统计或显示支持截图回读的区域数。生成成功仅表示写入完成，不保证水印能够从原图、截图或压缩图中恢复；请用解析功能测试实际保存的文件。编码布局、写入强度和解析流程沿用 5.1.2。

## 5.1.2 导频增强与压缩检查

以下记录描述 5.1.2 当时的生成行为；其中的自动回读与 WebP 检查已在 5.1.3 移除。

## 导频增强与压缩检查

本次仅提高有纹理区域的频域导频像素改动上限，从 ±2 灰度级提高到 ±3。平滑区域仍为 ±1，数据块仍为 ±2；暗部像素仍限制为 ±1，原有极暗、极亮及暗平滑区域排除规则继续生效。实际改动由 QIM 目标决定，上限增加不代表每个导频像素都增加强度。不能保证所有图片上都肉眼不可见，需要检查平坦背景和放大后的纹理。

512 个导频的位置、QIM 周期和基函数继续使用原布局，因此新旧普通频域水印使用同一套解析流程。四角色度标记未增加强度。

每次生成最终图片后，自动进行两组检查：整图先缩至原尺寸的 85%，长边最多 1600 像素，再分别以 Android 有损 WebP 质量 75、50 编码和解码。两个质量值是编码器参数，不代表压缩率或成功率。检查对象包含最终角点标记和 PNG 数据写入后的图像；模拟压缩副本只用于检查，保存到相册的仍为生成的 PNG。

每组显示：

- 模拟图片尺寸和质量参数。
- 已知区域回读数量：按生成时的区域边界同比缩放，直接检查完整消息，包含 CRC32，并与本次生成消息比较；这不能代表自动定位成功。
- 最高导频分数：对各区域完整的 512 个导频按读取规则统计，并搜索原有增益。可用导频数量与最高分数分别取各区域最大值，二者可能来自不同区域；这些数字用于诊断，不是解析成功判据。
- 自动定位是否找到候选，以及自动回读是否通过：使用角点搜索、必要时高清重试，候选直接读取后最多校正前 4 个区域。自动回读通过要求从压缩副本恢复完整消息并与本次消息一致。定位有候选并不保证是真实水印区域。

两组模拟检查会增加生成时间，界面持续显示当前检查进度。压缩回读失败或检查异常会显示结果，仍允许保存已通过原图校验的 PNG；程序不会自动继续提高强度。模拟检查不能覆盖所有软件的重编码、锐化、缩放或多次转码流程，仍需实际传输测试。

## 本次改动

每个区域仍包含完整的用户 ID、设备 ID、毫秒时间戳和 CRC32，完全离线恢复，不依赖本机记录或原图。

- 新生成的消息使用 WMK3 紧凑二进制格式，保留长度字段及 CRC32。
- 常见的 16 位小写十六进制 Android 设备 ID 保存为 8 个二进制字节，读取时恢复原字符串。其他设备 ID 保存原始 UTF-8，不截断内容。
- 常规时间戳保存为 6 字节整数；超出非负 48 位范围的值使用 8 字节，保留完整 Long 值。
- 频域编码分别保护 48 位数据头和实际长度的数据体，取消固定补齐到 512 位的消息填充。每段使用原有的 1/2 码率卷积纠错和 6 个零尾比特；编码更短后，在同一组频域位置上重复更多次，通过软判决合并恢复信息。
- PNG 直接读取、截图行扫描及频域解析兼容历史 WMK2 消息和固定 512 位编码。历史 WMK1 与已移除的 R5 频域格式不属于本版兼容范围。

5.1 引入紧凑编码时沿用了普通模式的强度与载体布局；5.1.2 的强度变化仅限上述有纹理区域的导频上限。此前产生明显纹理的 R5 模式已移除。

## 编码布局

WMK3 消息由 6 字节头、二进制内容和 4 字节 CRC32 组成：

| 字段 | 大小 |
| --- | --- |
| 标记 WMK3 | 4 字节 |
| 内容字节数，大端整数 | 2 字节 |
| 标记：设备 ID 是否压缩、时间戳是否为 8 字节 | 1 字节 |
| 用户 ID 的 UTF-8 字节数 | 1 字节 |
| 毫秒时间戳，大端整数 | 6 或 8 字节 |
| 用户 ID | 按实际字节数 |
| 设备 ID | 剩余内容，压缩时为 8 字节，否则为 UTF-8 |
| CRC32，覆盖前面全部字节 | 4 字节 |

普通频域载体共有 4096 个块：前 512 个逻辑块仍作导频，后 3584 个用于数据。新编码分配 768 块重复写入纠错后的数据头，另外 2816 块重复写入纠错后的实际数据体。解码先恢复头部获取长度，再恢复对应长度的数据体，最后验证完整消息的格式和 CRC32。失败时尝试旧版固定 512 位布局。

以 `用户 ID=123456`、`设备 ID=0123456789abcdef`、`时间戳=1792378692705` 为例：

| 项目 | 旧版 | 5.1 |
| --- | --- | --- |
| 完整消息 | 376 位 | 256 位 |
| 实际参与卷积编码的消息 | 补齐至 512 位 | 48 位头 + 208 位内容与 CRC |
| 单个纠错位的重复数，未扣除不可用块 | 约 3.46 次 | 头部约 7.11 次，内容约 6.58 次 |

实际重复数会受图像中可用块数量影响。短消息收益更明显；接近 512 位容量上限的消息，因为单独保护头部，内容部分重复数可能略低于旧版。单区域的完整消息容量仍为 512 位，超长时提示用户缩短 ID。

## 验证与设备测试

本次单元测试覆盖新旧消息、Unicode、设备 ID 两种表示、时间戳边界、CRC 损坏拒绝、不同频域消息长度（含 512 位上限）、模拟位置丢失和误码恢复，以及旧版固定布局兼容。Debug APK 已构建通过。

5.1.2 的 13 个 JVM 单元测试通过，Debug APK 和设备测试 APK 均编译通过。新增设备测试覆盖频域改动上限与原图回读、无水印黑图不得误报成功、压缩缩放后仍使用原区域布局以及检查不修改原图；设备测试尚未执行，真实 WebP 编解码结果与画质由设备测试确认。

在 Android Studio 中运行 5.1.2，使用相同用户 ID 和同一张载体图片重新生成，再分别测试保存的 PNG、软件传输后的全图以及保留完整区域的局部截图。记录生成结果中的两组 WebP 模拟检查，以及实际解析失败提示。若已知区域可回读而自动回读失败，应重点检查定位；若导频分数提高但消息仍无法回读，应继续分析数据载体。

实际软件传输流程上的成功率仍需设备测试。紧凑编码增加了数据冗余，本版只小幅提高部分导频强度；压缩若已抹掉定位标记或数据，仍可能失败。

2026-10-19 用户反馈：5.1 仍无法解析经过软件压缩的图片。5.1.1 保留当前实现并更新发布版本，未宣称修复该问题，后续需要结合新生成的原文件、压缩文件和失败提示继续诊断。

## 版本记录

- 5.1.3：移除生成时的回读校验和 WebP 模拟检查，缩短生成等待时间。
- 5.0：曾引入 R5 抗有损 WebP 模式。
- 5.0.1：因纹理过于明显移除 R5 模式。
- 5.1：在普通模式内加入 WMK3 紧凑编码与实际长度纠错、重复编码。
- 5.1.1：提交当前编码与定位改进，记录压缩图仍解析失败的已知问题。
- 5.1.2：有纹理区域的导频上限提高至 ±3，生成后加入缩放与 WebP 质量 75、50 的诊断回读。
